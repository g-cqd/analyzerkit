## First pass, from reading

A plan was written from the code alone. Its claims were then probed one by one, because a reading is not evidence
(ADR-0002). The verdict table is research `2026-10-29-index-store-reports-reviewed.md`; the sources are in
`research/probes/`.

## What the probes changed

- **A4 is worse than read.** After `class Plugin` became `struct Plugin` in a file the build had not seen, arcleak said
  "index store active" and reported an *error* (`stored-closure-strong-self`) from the stale record.
- **A6 and D1 have a side effect.** A wrong `--index-store-path` (`<DerivedData>` or `…/Index.noindex`) makes both tools
  create `v5/` and `IndexDatabase/` inside that directory; it is reported as "stale" (arcleak) or "does not cover"
  (deadwood).
- **D4 is worse than read.** The owner's `Xcode.app` is user-owned; deadwood refuses Xcode's own `libIndexStore.dylib`
  and silently loads Command Line Tools' copy, which only works because both are Swift 6.4 today.
- **A5 on the real project.** A fresh DerivedData index of the exact worktree exists; both tools say "no index store
  found", because they match DerivedData by the folder's name (`parts-MAIN-24752-stock-handling`, not
  `Oculavis Share IOS`). Two worktrees of the project have DerivedData folders with the same prefix: only `info.plist`
  `WorkspacePath` separates them.
- **A1 at scale.** 62 of 2,830 maintastic files make arcleak drop the index for all, after a 9.4 s, 128 MB import.
- **F1 has a twin.** A helper written with an implicit return (`{ open(…) }`) is never an acquirer (F1b). K1 also prints
  "throws at line 0" (F6).
- **K3 confirmed.** `fallthrough` goes past the switch; `break outer` out of a labelled `do` or `if` has no successor.

## Retracted or refuted

- **The `/tmp` symlink "stale store".** My first fixtures used `swiftc -typecheck`, which records no per-file unit; every
  file then looks stale. With `-emit-module`, `/tmp` and `/private/tmp` paths both work. Retracted.
- **A3b** (an `extension Foo` occurrence makes the lookup fail): the cycle is still found. Refuted.
- **A7** (concurrent arcleak and deadwood corrupt the shared database): three concurrent runs on a fresh database,
  identical results (115 deadwood findings each). Refuted; the location problem (writing into DerivedData) stays.
- **D2's impact.** The mechanism is real (a fixture shows `helper()` reported dead when its only use is in an unindexed
  test), but no non-trivial finding of maintastic's 115 comes from it.

## The reports' framing, corrected

arcleak's report asked for a decision per *analyzed* file; the index answers about types the corpus does not declare, so
the declaring file of the answer is what must be fresh (ADR-0005). Most of maintastic's "stale" files are files no scheme
builds, not files changed since the build.

## Hygiene

Every probe file was removed after its run; every repository and the maintastic worktree were left clean. The DerivedData
store was copied to `/tmp` (with `cp -Rp`, so unit timestamps hold) to keep the tools from writing `IndexDatabase/` into the
owner's DerivedData.
