## 0043: probe

maintastic's project has no explicit sources at all. Sixteen synchronized folders hold everything, and six exception
sets do the opposite of what their name suggests. For a target that owns the folder, an exception removes the file;
for any other target it adds the file. The NotificationExtension folder belongs to no target, and its one source gets
in only through an exception. One file is compiled by both the app and its UI tests. One script phase runs a Swift file
and also lists that file among its outputs, so "output means generated" needed a rule saying the script wins.
`PropertyListSerialization` took 556 ms on the file. It is also Foundation-only, so we read the OpenStep grammar
ourselves: it is small, and our reader takes about 5 ms. All 17 manifests list their targets literally, so syntax was
enough for every one of them. The dynamic shapes we refuse come from the wider ecosystem, not from this corpus.

## Red, green

Eighteen tests, with fixtures written as real `Package.swift` and `project.pbxproj` text: tabs, comments, quotes and
escapes. Sixteen were red against the stub. The two that passed are guards: the reader refusing broken input, and no
project at all. The green passed them on its first run. Two decisions are worth keeping:

- **Test needs every target to be a test target.** A shared source ships in the product, so findings about it count as
  production.
- **Unknown is never silent.** An unreadable manifest or project, or a file no target compiles, still gets the
  conventions' answer, but the provenance says why and `issues(for:)` reports it.
