# 2026-10-29 (19) — Roadmap 0007: source discovery on the walker

## Three pins before one line of code

analyzerkit could not take the new aemi alone: AemiJSON pins aemi too, and SwiftPM refuses two revisions of one package in
a graph. So aemi first gained `Policy.maxDepth` (red, green, on a branch in the side worktree; another session had pushed
to aemi's `main` meanwhile, unrelated files, so a rebase and a rerun of the suite before pushing), then AemiJSON moved to
that aemi (429 tests green), then analyzerkit to both. The depth bound came first so the pins moved once: `ProjectLayout`
needed a one-level listing, and without a bound the walker would have opened every subdirectory of the temporary
directory to refuse their contents.

## Red

Before touching the walk, a throwaway test dumped today's lists on nine trees (maintastic, the six analyzer repositories,
aemi, swift-syntax). Then red against stubs over today's code: no stat for an entry the listing typed (the stub reports
-1, since today's walk cannot count what Foundation does), unreadable directories reported, a link inside the root listed
once at its target's path, exclusion by real location, an ancestor typed without opening its subdirectories.

One expectation was mine, not the code's: I wrote that a link named `Linked.xcodeproj` to a project counts as a container.
It never did; the old check used `attributesOfItem`, which does not follow a final link. Corrected to today's behaviour
rather than changing it in passing.

## Green and measured

The dump after: no difference, 4,704 files and 34 manifests. All five tools' suites green with their report goldens; one
source change in a tool (arcleak's `ProjectFileDiscovery` passes a predicate that now has to be `@Sendable`).

On maintastic, alternating the previous release binaries (built in throwaway worktrees) with the new ones, seven runs each,
JSON byte-identical: arcleak 752 to 368 ms, dolly 893 to 703 ms; discovery alone 232 to 24 ms. `ProjectLayoutTests` 15.0
to 1.0 s, which was the stall that started the configuration-lookup work.

## Decided not to do

Streaming the walk into `CorpusScanner`: 24 ms is the most it can save on a 368 ms run, against a new scan entry point in
every tool. Written into 0007 with the numbers.

## Noticed

- ADR-0022 says Linux opens with `openat2` and `RESOLVE_NO_SYMLINKS`; aemi's code opens component by component with
  `O_NOFOLLOW`, which works on any Linux but costs a descriptor per component. Settle it when the Linux build first runs
  (end-of-train CI).
- No tool reports an unreadable directory: 0046.
