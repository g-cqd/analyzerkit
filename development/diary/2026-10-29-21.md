# 2026-10-29 (21) — Roadmap 0010: IndexStoreSupport

## Interner naming, and where the interner goes

The owner asked whether `FrozenInterner` should be `SendableInterner`. Kept: "frozen" names the property that makes it
shareable, immutability; `Sendable` names a consequence that a locked mutable interner would share. Easy to rename while
nothing uses it. The interner's consumers are now one item, 0047, and 0023, 0024 and 0027 adopt it without the "if the
probe shows a gain" they had.

## Three steps

Locating and coverage first, with no IndexStoreDB: the A6/D1 probes became tests on hand-made trees, and coverage a pure
function of two dates per file. The first `v5` case resolved to `v5` itself, which holds records directly; IndexStoreDB
must be given the root, so a version directory's parent is tried first.

Then the session, on stores the compiler writes in the test (`swiftc -index-store-path`, as the probe script does). The
gate is in the API: a database is handed out only with a usable coverage. A store built with `-file-prefix-map` was the
relative-path fixture, and it first came out usable: swiftc sees the temporary directory as `/private/var/…`, so a map
written for `/var/…` did not apply. With both spellings mapped and relative inputs, it is refused, as a store with relative
units must be.

That fixture led to a correction of arcleak's own comment: it skips `.build/out` because "Swift Build records relative
unit paths". On Swift 6.4, analyzerkit's own `.build/out/v5` opens and answers for an absolute source path. The shared
discovery includes it, and the coverage gate stands between a relative store and any query either way.

Then the executor. The two forks agreed on the environment and differed in everything else; neither capped output. The
test that a child ignoring SIGTERM is killed takes 4.3 s: deadline, grace, and the drain grace, because `sh`'s own `sleep`
outlives it and holds the pipe. That grandchild is orphaned, not killed: Foundation's `Process` cannot start the child in a
process group of its own.

The owner suggested swift-subprocess, which can (`createSession`) and has teardown sequences aimed at a process group. Red
first: a grandchild that ignores SIGTERM must not survive a timed-out child (it did: an ignored signal survives `exec`,
and Foundation's termination reached the child only), and the ignoring child must go within the grace (4.3 s before).
Rebuilt on Subprocess 1.0.2: the child gets a session; on the deadline or a cancellation the body signals the group itself
before throwing, because Subprocess skips its teardown when the direct child is already gone, and only then is the
group's id still reserved by the unreaped child. 2.3 s, no orphan; ten repeated runs clean. One regression on the way:
Subprocess tears a cancelled task's child down itself and its outputs then end normally, so the run returned a result;
it now checks for cancellation before returning. Subprocess is async only, and bridging it to a blocking call would park
a cooperative thread, so the executor and the toolchain resolution are async now; arcleak and deadwood adapt in 0018 and
0019, where their readers go anyway.

## Dependencies

indexstore-db: the tools pin `64aa0b2`, on neither upstream `main` nor `release/6.3`. analyzerkit pins `main`'s head,
`0390867`, which adds parallel record reads (the A1′ import took 9.4 s); the tools move when they adopt (0018, 0019).
