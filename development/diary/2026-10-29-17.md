# 2026-10-29 (17) — Roadmap 0014: one configuration, and the cost of finding it

## Probed first

Four probes before any code. An unknown key, at the top level or nested: arcleak, deadwood, dolly and fcheck all exit 0,
the key ignored; `{"exlude": [...]}` silently excludes nothing. A malformed `.arcleak.json` at the repository root, run
from `Sources/`: exit 0, the file never read; every tool reads its file from the current directory only. The files in use
hold only known keys (maintastic's three, the g-cqd packages' `.deadwood.json`), so rejecting unknown keys breaks none of
them. AemiJSON has a JSON value, an RFC 7396 merge and duplicate-key rejection, and FoundationEssentials has no
`JSONSerialization`: the reader merges AemiJSON values and hands each tool one merged object for its own decoder, so every
tool's types and checks stay as they were. ADR-0020 superseded ADR-0007 on those facts.

## A stall, a full disk, and a fixture that collided

Adopted, deadwood's full suite stopped progressing: each command-line test spent over a minute before analysing. The
lookup used `ProjectLayout`, which lists every ancestor up to the repository root, or to `/` outside one, and walks the
project tree for manifests. Those tests run outside a repository, under the system temporary directory (262,000 entries).
A configuration lookup needs neither: ADR-0021 finds the directory by two `stat` calls per level, nearest first, up to the
repository root, and outside a repository looks nowhere but the current directory. The configuration tests went from 22 s
to 0.04 s; deadwood's suite is back to its usual 138 s.

Earlier, a Libtool step failed with ENOSPC: the 30 GiB work volume was full. Removed only the release builds of the five
tools (about 2 GB, rebuilt for the next maintastic measurement); left `ask/.build`, which the running agent executes
from, and every other repository. The run that died was the red run of one small change (`reason`); its red was not
observed, which roadmap 0014 says. Two `swiftpm-testing-helper` processes days old, not from this work, were left alone.

The tool adoption tests had their own bug: for deadwood, the template's "another tool's section" was `"deadwood": {}`
beside the tool's own `"deadwood"` section, so the second silently replaced the first. That is the very failure ADR-0020
forbids, so the reader now rejects a key given twice at any depth (red, then green), and the template uses another name.
An arcleak deadline test failed once while the machine was saturated by the stalled suite; it passed on the rerun at the
normal 22 s, and nothing it covers changed.
