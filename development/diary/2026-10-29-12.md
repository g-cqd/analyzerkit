# 2026-10-29 (12) — Roadmap 0009: shared toolchain resolution and trust

## Red, then green

Added IndexStoreSupport now, with no IndexStoreDB dependency yet: a filesystem/toolchain policy needs no index reader.
Six initial shared tests failed against a resolver returning nil and a trust stub refusing everything. Implemented
DEVELOPER_DIR, xcode-select, xcrun, user snapshots and CLT in that order, stopping on a trusted candidate. Added ownership,
CLT/all-rejected and malformed-path coverage: nine shared tests green. The full analyzerkit suite is green too.

The resolver canonicalizes before trust and returns that exact spelling. Regular file, owner root/current user, no
write permission for group/other on the file or its immediate parent. Symlinks follow the target's policy, not a blanket
rejection. Relative paths and embedded nulls lose. Fixed absolute probes with a scrubbed environment: no caller PATH
or DYLD injection; xcode-select is independent of DEVELOPER_DIR, xcrun receives it explicitly. The .app spelling is
accepted as well as Contents/Developer. Rejection diagnostics retain source, path and reason; lower priorities are not
probed after a winner. No hard-coded /Applications/Xcode.app policy remains in either tool.

## Adoption found another bypass

Three red tests per tool: writable parent and trusted symlink behavior; --verbose stderr diagnostics with identical
JSON/exit status; explicitly supplied unsafe dylib. The last failed because both reader initializers bypassed their
checkers for explicit paths. Arcleak even created an IndexDatabase before failing dlopen on the fixture's fake library.
Both now reject before database creation or dlopen, returning dylibNotFound. Existing BinaryTrustChecker names are tiny
compatibility wrappers, not copied policy. Typealiases were insufficient under MemberImportVisibility, which requires
every client to import the defining module for its members; wrappers retain source compatibility without policy copies.

Both sync and async arcleak paths, and deadwood's sync path, use the same resolver. --verbose is accepted by both CLIs,
prints only for requested index mode, and keeps discovery diagnostics out of the structured report. It describes a
selected candidate, not proof of dlopen or coverage. A verbose invocation resolves twice (diagnostics then opening),
not once per file; consolidating reader state belongs to 0010.

## Actual library loading, not a silent skip

A throwaway shared probe asserted the selected Xcode path. A throwaway test in each tool then required its selected
path to be under Xcode.app, compiled a temporary Probe.swift with the matching swiftc, opened a default IndexStoreReader
and required its per-file unit timestamp to exist. Both passed, selected the exact XcodeDefault toolchain library, and
read the unit (0.171 s arcleak, 0.166 s deadwood, single debug probe runs, not benchmarks). No test silently skipped.
All scratch trees cleaned up and probes removed. No maintastic index opened or consumer modified.

Full suites: arcleak 211 tests, deadwood 369; shared suite and records gate green. Commits in roadmap 0009, pushed.
Deadwood's earlier wave-0 test expected every symlink to lose; it now asserts ADR-0014's resolved-target semantics.

## Limits and next work

This is the filesystem selection/trust milestone, not the reader migration. Store-unit compiler mismatch notes need
reader metadata and are explicitly in 0010. The two small fixed system probes remain synchronous/timeout-free, like
previous synchronous discovery; 0010 owns bounded process lifecycle and output consolidation. Checks are not a race-free
security boundary and inspect only the immediate resolved parent, as documented. No Linux/CI work or release builds in
this pass. Next scheduled foundation: 0012, shared suppression, before report envelope/CLI/config harmonization and
then the reader migration (0010).
