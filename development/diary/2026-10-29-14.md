# 2026-10-29 (14) — Roadmap 0011: the report envelope, and what the goldens found

## A decision before code

ADR-0009 added `tool` (an object), `notes` (objects), `skippedFiles` and `timings`. The survey of shipped reports: deadwood
already writes `notes` as `[String]`, fcheck `tool` and `version` as strings. ADR-0009's own first rule forbids retyping a
key, and `ReportSchema` counts removing one as a version change. ADR-0017 supersedes it: `tool` and `version` as strings
(fcheck's spelling, for everyone), `runNotes`, `skippedFiles`, `timings`; old keys kept for the life of version 1; no
breaking schema release planned at all. Also: fingerprints keep each tool's hash and inputs (ADR-0016 said XXH64 would
replace FNV-1a "where they fingerprint", which would have invalidated every baseline in use). maintastic's decoder reads
`schemaVersion` and six finding keys, so nothing it reads moves.

## Goldens that do not depend on the checkout

First recording, in the source tree: SARIF holds the absolute `SRCROOT` uri, and arcleak classifies code under `Tests/` as
test code, which changes messages and so fingerprints. Second, from a temporary copy: fingerprints changed per directory.
Not a bug: outside a repository `RepositoryRoot` keeps absolute paths, by design. The copy is made a repository root (a
`.git` file), as a corpus is in real use; then outputs are stable and the baseline's fingerprints equal the reported ones.
SARIF's `SRCROOT` uri, absolute by design, is the one value replaced by a placeholder on both sides.

The non-UTF-8 input could not be committed as `.swift`: the pre-commit hook lints every staged Swift file and cannot read
it. Bypassing the hook was not an option taken; the file is `Bad.swift.bytes` and the copy renames it.

## A bug found: 0044

fcheck's SARIF stayed different between two copies even in a repository root: every location, primary and code-flow, was
an absolute `file://` uri, while the log declared `SRCROOT`. `ArtifactURI.location` takes the path as the report spells it,
relativized; the other tools relativize first, fcheck did not. From CI, code scanning would get runner paths. Red
`fd065b2`, fix `853fe5a`; the fcheck golden was recorded after the fix.

## Envelope

ten-path cap with a full `count`, the four reasons, the summary phrase), then green, pushed together. Each tool: goldens
red only on the envelope keys and the "(N not checked)" summary, then green after adoption. The JSON contract tests that
pin the exact key set gained the four keys, the deliberate contract change of ADR-0017. Full suites green.
