## Design, then red

A shard is an AemiProtobuf message: identity, the run's start time, the salt's hash, entries. Mapped, walked with
`WireReader`, payloads located with `readPayloadRange` and decoded only on a hit. Files are replaced by rename, so a
mapping never sees its file shrink. Twenty-two tests against a stub with no cache: twelve red; ten passed because a
cache-less scanner cannot break them (no identity, salt, a size-and-mtime-preserving edit, cancellation, budget), kept as
guards. One of them caught a real bug in the green: a stat-key hit did not look at the salt.

## Measured, and a correction to the measurement

The first probe ran in a debug build and showed the warm run (91 ms) slower than reading every file (64 ms); in release
it is 47 against 39, and split up: canonicalizing 25 ms, decoding payloads 26 ms, stat 2, shards 2. The container itself
costs about 4 ms; what remained was canonicalization, here, and payload decoding, 0017.

Canonicalization resolved every file whole. Red through a resolver seam (61 paths in three directories with a link: at
most four resolutions), plus an equivalence test over links, dangling and missing files, `/private` and relative
spellings. The first green was slower, 67 ms: it standardized every path through `URL` and split it through `NSString`.
Checking the bytes for an already standard absolute path and splitting on the last separator brought it to 15 ms, and on
maintastic's 2,980 files every spelling equals resolving it whole.
