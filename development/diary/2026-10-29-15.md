# 2026-10-29 (15) — Roadmap 0011 closed: one SARIF, one baseline file, one path rule

## Method

The goldens of entry 14 made every step a refactor with a byte-level check: SARIF, xcode and the baseline file must not
move by a byte, JSON only by ADR-0017's keys. Each shared piece was red in analyzerkit first (a stub, then the real
thing), then adopted by the four tools, then their full suites.

## SARIF

The four copies differed only in optional members: related locations (arcleak, dolly with a "duplicate region" label),
result properties (deadwood's confidence), rule properties (arcleak's tags, fcheck's shape and evidence), `help` versus
`fullDescription` and `defaultConfiguration` (fcheck), code flows (fcheck, written as `[]` when empty), invocations (not
in fcheck), an optional start column (fcheck's witness steps). One model with optional members omitted when nil covers
them; fcheck's always-present `codeFlows` is a non-nil empty array. Each tool keeps its encoder: Foundation's for three,
AemiJSON for fcheck, and both produce the recorded bytes. About 630 lines of copies gone.

## Paths and baselines

`PathPresenter` is the rule (canonical root, prefix stripped from paths inside it and from free text); which fields go
through it stays per tool, because the tools differ there (arcleak leaves a degraded file's detail as is, dolly and
deadwood strip it) and the goldens pin that. `BaselineFile` is the file: sorted unique fingerprints, tool, and
`version: 1` except fcheck's. A tool's fingerprint is its own (ADR-0017). Two behaviour notes: a version-less baseline
now gets a plain message in the three versioned tools; fcheck now refuses a baseline with a version other than 1.

## Xcode lines

Small, but it was four spellings of one format Xcode parses. `XcodeDiagnostic.line` with an optional rule (fcheck's
witness notes have none).
