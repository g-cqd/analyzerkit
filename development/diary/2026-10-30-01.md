# 2026-10-30 (01) — What swift-search gives the family; one indexstore-db requirement

## The pin probe

swift-search's report left one case unprobed: a revision in one package against a branch in another. Five small packages
settled it. SwiftPM refuses any two requirements written differently, even a revision and a branch that name **the same
commit** (`64aa0b2` is today the head of `release/6.4.x`). Only identical spellings resolve. Nothing conflicts today
because dolly, fcheck and modeler pin analyzerkit `3032271`, from before IndexStoreSupport; the first tool to take the
head will conflict.

The report recommended O1, `branch: "release/6.4.x"` everywhere. Before agreeing I measured what `main` was chosen for:
the same probe built against each revision, on maintastic's Xcode store. Import and name lookups are equal. Reading every
occurrence of 121 common symbols (106,301 occurrences) takes 1.14 s on `main` and 2.24 s on the release branch, with the
same counts: that is the concurrent record reading `release/6.4.x` does not have, and it is exactly what deadwood and
arcleak do. ADR-0025 keeps the revision of `main` and requires every package to write it the same way. The load average
was 40–144 during these runs; the ratio held in all four pairs.

## The thirteen proposals

ADR-0027 gives each proposal a verdict, counting the consumers in the tools' code rather than imagining them. Every
tool builds absolute paths from `currentDirectoryPath` by hand. arcleak's index path does it without canonicalizing,
which is swift-search's `/private/var` defect again, so P11 has six consumers. No tool parses doc comments (P13 stays)
and none runs an interactive child (P6 stays, with its trigger written down). P9 turned out to be a deletion: deadwood's
`SafeRegex` and `RegexCache` guard Swift `Regex` against backtracking, and AemiRegex has none to guard against.

P6 was first filed as a "deferred" roadmap entry; the records gate allows only not-started, in-progress and done. Rather
than add a status for one entry, its trigger moved into ADR-0027 and the entries after it were renumbered.
