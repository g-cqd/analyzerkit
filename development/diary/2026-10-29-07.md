# 2026-10-29 (7) — Roadmap 0004: the repository root, once per directory

`RepositoryRoot` had no tests. Before changing how it searches, six characterization tests pinned its answers on real
temporary trees: a clone (`.git` directory), a worktree (`.git` file), a repository nested in another, a file outside any
repository, a directory given as `dir/.` (what `workspaceKey` passes), `common` agreeing or not, `relativize`. They pass on
the old code. One quirk was left unpinned on purpose: a bare directory path is searched from its parent; callers avoid it.

Red: the `.git` check became an internal seam with the same algorithm, and a test counted it: 3,000 probes for 1,000 files
in 10 directories three levels deep. Green: a per-call memo from directory to root (or to none); a walk stops at the first
directory already answered and records the answer for every directory it passed. At most 13 probes; every other test
unchanged.

Through dolly (local `swift package edit`, release build, maintastic, 2,873 files): the JSON report is byte-identical
(200,678 bytes); warm runs, interleaved old and new, five each: 1.03 0.93 0.92 0.92 0.93 s against 0.88 0.83 0.83 0.84
0.83 s. About a tenth of dolly's warm run, as the profile predicted (171 of its main-thread samples). The other tools get
the same once they pin this analyzerkit.
