# 2026-10-31 — the maintastic rules, and where each belongs (0062 to 0066)

All four proposals of the morning are in, and released: fcheck 0.4.0, modeler 0.4.0, arcleak 0.15.0.

`continuation-overwrite` moved from modeler to arcleak before modeler released it. A dropped continuation is a
leaked caller, and arcleak's rules are about lifetime; a check across an `await` or across locks is modeler's, a path
obligation fcheck's. arcleak keeps no false positives, so the rule there is narrower than modeler's draft. Any condition
before the store may be how the code keeps a second call out, and it then stays silent. It still finds maintastic's one
case.

Running each new rule on maintastic before committing caught three false positives that the tests had not:
modeler counting an awaited call in a condition as a check, fcheck taking a checked `CVReturn` for a held lock, and an
unlock of `pixelBuffer!` not matched. Each is a test now. The family's repositories, all twenty, were the second
check, and nothing in them moved.

modeler's TLA+ model is useful on `RecordingCoordinator` now. Its first traces started from states the code refuses,
because of a guard on a computed property, a `switch` that throws on the other cases, and a monitor that took the
method's own claim for someone else's write. With those fixed, TLC finds the interleaving that `check` reports.
